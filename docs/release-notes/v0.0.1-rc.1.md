# v0.0.1-rc.1: release candidate for v0.0.1

A release candidate: the same content planned for v0.0.1, published to test
the release pipeline and the signed builds on a real phone before v0.0.1.

koiTerminal with a development control plane: a separate agent app, **devd**,
lets a paired computer drive the app's **dev** build over mutually
authenticated TLS, without keeping ADB switched on and from wherever you can
reach the phone. Everything upstream koiTerminal does still works. This is an
early developer preview: the control plane works from the command line, but
it is rough in places.

## Downloads

| File | What it is | Signed with |
|---|---|---|
| `koi-0.0.1-rc.1.apk` | The app, `prod` build: upstream koiTerminal under this fork's package name, with none of the development pieces | prod key |
| `koi-0.0.1-rc.1-dev.apk` | The app, `dev` build: the same app plus the hook service devd talks to | dev key |
| `koi-devd-0.0.1-rc.1.apk` | devd, the development agent | dev key |
| `koi-ctl` | Command-line client for Linux (x86_64, static) | (checksummed and attested) |

The `prod` and `dev` builds share the package name
`io.github.franticplant.koiterminal` and are signed with different keys, so
only one of them can be installed at a time. To switch, uninstall the other
first; that removes its VM and data.

## What you can do with the dev build and devd

- Pair a computer with `koi-ctl pair`. You confirm a matching code on the phone
  and choose what that computer may do; pairings expire.
- Start, stop and restart the VM, read its status and why it last stopped,
  change settings and port forwards, and read the app's logs and metrics.
- Push your own kernel, initramfs and disk files to the phone (resumable and
  checksum-verified) and boot them through a boot profile, without touching
  the installed image.
- Use the VM's serial console from your computer: `koi-ctl console`.
- Update the app and devd from your computer with `koi-ctl update`.

devd's listener only runs while you have it switched on, binds to loopback
unless you choose interfaces, and switches itself off after 60 minutes by
default. See [`docs/devd.md`](../devd.md).

## Install

1. Uninstall any koiTerminal or devd you built or installed from elsewhere:
   a different signing key cannot update over it.
2. Install `koi-0.0.1-rc.1.apk` for normal use, **or** `koi-devd-0.0.1-rc.1.apk` and
   `koi-0.0.1-rc.1-dev.apk` for development.
3. Grant the VM permissions once, as described in the README (this needs ADB,
   once per install).
4. For development: open devd, start the listener, then pair with
   `koi-ctl -a <phone>:7391 pair`.

## Known limitations

- Kernels packed as EFI "zboot" images (for example Alpine's `vmlinuz-virt`)
  do not boot directly; use a raw arm64 `Image` such as Debian's netboot
  kernel.
- Booting installer ISOs and UEFI firmware is not supported yet.
- Pushing files runs at about 3 MiB/s, which is fine for kernels but slow for
  large disk images.

## How this release was made

- Built by GitHub Actions from the tag, twice on separate runners with no
  shared caches; the two builds were identical before anything was signed.
- Signed only in CI, from keys that never leave the GitHub release
  environment. The prod app and the dev app/devd use different keys; both
  certificates are committed in `dev/signing/`.
- Every file has SLSA build-provenance and SBOM attestations. Rebuild and
  compare it yourself with `scripts/verify-reproducible.sh v0.0.1-rc.1`.
- Based on upstream koiTerminal at `12de8af46b5f1291017e0380c8123edf632e4ba8`
  (2026-10-12).
