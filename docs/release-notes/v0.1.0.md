# v0.1.0 — fork identity and the devd control plane

This is the first release of the standalone fork under its own identity:
`io.github.franticplant.koiterminal` for the app and
`io.github.franticplant.koiterminal.devd` for the development agent. It is a
prerelease; the app still needs the manual permission grants described in the
README.

## What changed

- The standalone build has its own package identity, signing pin and release
  scripts. The AOSP/OS build keeps its original namespace.
- The app has `dev` and `prod` flavors. `dev` exposes a signature-protected
  DevHooks service and a VM-oriented method table; `prod` contains neither.
- `devd` is a separate APK with a TLS 1.3 listener, client-certificate pairing,
  scopes, a hash-chained journal, metrics and an updater for the app and for
  itself.
- `koi-ctl` pairs from a laptop, calls the typed API, reads devd/app logs,
  checks journal anchors, and uploads app/devd APKs with digest and signer
  verification.
- Stopping the listener or unbinding an interface closes established
  connections. A pairing request cannot be published after stop.
- `scripts/check` is the host-side gate; `scripts/build` / `scripts/sign`
  produce the APKs.

## What is not claimed

The devd update loop has not been exercised on a phone yet. First-install
confirmation, update-owner establishment, foreground-service restrictions,
Binder restart timing, VM/guest operations and network permission denial are
device-only checks.

## Install

Install devd first, then let devd install the app (or install both from adb for
bootstrap). Both packages must be signed with the same key. See
[`docs/devd.md`](../devd.md).
